# 3D Scanner Reference Mapping

This document maps selected `reference_osv/src/osv/FaultOrientScanner3.java`
methods and helper classes to the current `pyosv.orient3d` implementation.

The current default Python scanner is reference-like but approximate. It rotates
the volume by strike, smooths in rotated coordinates, sweeps dip with
shear/unshear interpolation, and unrotates candidate likelihoods using SciPy
operations by default. An opt-in structured linear backend uses the same
transform geometry without full coordinate grids. The older derivative-bank scanner remains available through
`scan_fast()`, and the previous direct fault-parallel smoothing approximation
remains available through `scan_reference_like(..., backend="directional")`.
The entries below therefore describe approximations and gaps, not exact
equivalence.

`SincInterpolator` and `RecursiveExponentialFilter` are Pythonic approximation
targets. They are not hard dependencies for `pyosv`, and no JVM, Jython, Mines
JTK, or Gradle runtime dependency should be introduced.

## Method-Level Mapping

| Java method / class | Python equivalent / status | Reference behavior summary | Current Python behavior | Known difference | Parity tests | Future reference-like implementation required |
| --- | --- | --- | --- | --- | --- | --- |
| `FaultOrientScanner3` constructor | `FaultOrientScanner3.__init__` | Stores strike and dip smoothing half-widths as `_sigmaPhi` and `_sigmaTheta`; the overload with `power` does not currently use that argument in the inspected reference path. | Validates positive finite `sigma1` and `sigma2`, storing them as dip and strike scanning controls. | Parameter names and validation differ; Python has no unused `power` overload. | Python constructor validation regression tests exist; no Java parity test. | No for the current public API. |
| `scan(phiMin, phiMax, thetaMin, thetaMax, g)` | `FaultOrientScanner3.scan` | Builds Java sampling objects, rotates input for each strike, applies strike smoothing, scans dips in rotated slices, unrotates results, clips likelihood/dip ranges, and keeps the best strike/dip. | Delegates to `scan_reference_like(..., backend="rotate_shear")`, which validates `(n3, n2, n1)` `float32` input, handles constant volumes, uses Java-inspired strike/dip sampling, and runs the rotate/shear reference-like path. | SciPy interpolation, Gaussian smoothing, fill values, angle sampling details, and edge handling still differ from Java/JTK. It is not a bit-exact Mines JTK port. | Python synthetic localization and scan/vote regression tests exist; F3 comparison is report-oriented; no method-level Java parity test. | Further F3 scanner-only comparison and tuning remain future work. |
| Reference-like scan entry point | `FaultOrientScanner3.scan_reference_like` | Facade for the Java-style strike rotation, dip shear, smoothing, unrotation, and best-orientation workflow. Java converts smoothed semblance with repeated squaring and `1.0f - st`. | Deterministic orientation sweep: validates the same angle/image inputs as `scan()`, including scoring and interpolation backends, uses Java-inspired strike/dip sampling, converts likelihood with `1 - smoothed**4`, and keeps the best strike/dip. `backend="rotate_shear"` and `interpolation_backend="scipy"` are the defaults; structured linear interpolation is opt-in for order 1. | The default uses SciPy approximations rather than JTK `Rotator`, `SincInterpolator`, or `RecursiveExponentialFilter`; the structured backend changes only transform sampling. The directional backend is structurally farther from Java than the rotate/shear backend. | Python tests cover validation, deterministic output, normalized ranges, constant volumes, backend selection, primitive interpolation agreement, low-planarity synthetic planar response, and a small gated F3 backend smoke path. | Further F3 scanner-only comparison and tuning remain future work. |
| `scanTheta(...)` / dip sweep equivalent | `_scan_theta_shear_reference_like` for `backend="rotate_shear"`; `_scan_orientation_bank` only for `scan_fast()` | For each rotated `i2` slice and dip angle, shears by `-1/tan(theta)`, smooths along axis 1 with sigma scaled by `sin(theta)`, unshears, applies a semblance power transform, and keeps the best dip. | The rotate/shear backend shears each rotated slice with SciPy interpolation, smooths along the sheared dip axis with Gaussian filtering, unshears, and converts planarity to likelihood with `1 - smoothed**4`. `scan_fast()` still loops over strike and dip samples using Gaussian derivative responses. | Python smoothing axis, interpolation kernel, boundary behavior, and shear bounds are approximate; the derivative-bank path remains unrelated to Java `scanTheta`. | Python scan regression tests cover output shape/ranges, backend behavior, and synthetic behavior; no `scanTheta` Java parity fixture. | Further parity testing can refine this approximation. |
| `thin(float[][][][] flpt)` | `FaultOrientScanner3.thin` | Smooths likelihood in selected horizontal directions, then uses strike-binned 2D neighborhood comparisons in the `i2-i3` plane; zeroes strike/dip where likelihood is not retained. | Default `mode="reference"` uses `reference_like_3d_thin_values` for strike-binned suppression; explicit `mode="normal"` samples plus/minus one fault-normal step with `interp.sample3`. | The default is reference-like, but remains an approximation with SciPy smoothing and repository shape/dtype conventions rather than a bit-exact Java/JTK port. | Python normal and reference-mode thinning tests exist, including helper-level reference-like bins; no Java bit-exact parity test. | Further audit can refine the reference-like approximation. |
| `smooth(flstop, sigma, p2, p3, fl, g)` | `filters.smooth3d` / Gaussian derivatives | Builds local tensors from slopes and likelihood mask, then applies `LocalSmoothingFilter` with anisotropic directions. | Generic `smooth3d` wraps SciPy Gaussian filtering; scanner internals use Gaussian derivatives instead of this tensor smoothing method. | No local tensor smoothing, likelihood stop mask, or JTK filter behavior in the scanner. | `smooth3d` has Python regression tests for shape, dtype, constants, and impulse behavior; no tensor-smoothing parity test. | Required only if a future issue needs this Java smoothing behavior. |
| `shear(...)` / `unshear(...)` | `_shear2`, `_unshear2`, `_shear_rotated_volume`, `_unshear_rotated_volume` | Uses `SincInterpolator` to shear each 2D slice horizontally by a slope tied to dip, expanding and restoring slice bounds. | Uses SciPy `map_coordinates` by default or opt-in direct linear sampling, with constant fill in both cases. Near-vertical dips map to zero shear, and very small `sin(theta)` cases are clipped to finite shear values. | Python keeps same-shape arrays instead of reproducing Java null-slice/bounds handling, and uses linear interpolation rather than JTK sinc interpolation. | Python tests cover SciPy/structured agreement, boundary behavior, and near-vertical shear stability. | Further parity testing can refine bounds and interpolation behavior. |
| `Rotator` private class | `_rotate3_axis1`, `_unrotate3_axis1` | Rotates and unrotates volumes in the `i2-i3` plane for each strike, computes expanded rotated sampling bounds, and uses sinc interpolation tables. | Uses SciPy `map_coordinates` by default or opt-in direct bilinear sampling to rotate into an expanded finite array and unrotate back to global `(n3, n2, n1)` shape. | Python radius calculation, fill values, linear interpolation kernel, and edge behavior differ from Java `Rotator`. | Python tests cover finite float32 shapes, boundary behavior, and SciPy/structured agreement. | Further parity testing can refine rotated bounds and interpolation behavior. |
| `SincInterpolator` usage | `interp.sample3` / scanner-local SciPy sampling | Samples rotated, unrotated, sheared, and local directional values with JTK sinc interpolation and configured extrapolation. | `interp.sample3` and scanner-local helpers wrap `scipy.ndimage.map_coordinates` in the relevant coordinate order. Scanner thinning uses linear sampling with nearest boundaries; rotate/shear scanning uses constant fill values. | Kernel, extrapolation, coordinate bounds, and dtype behavior differ from JTK sinc interpolation. | `sample3` has Python coordinate-order and interpolation regression tests; rotate/shear helper tests cover shape and finite behavior. | Further parity testing can refine interpolation behavior. |
| `RecursiveExponentialFilter` usage | `filters.smooth*` / SciPy Gaussian smoothing | Applies recursive exponential smoothing for strike and dip-oriented smoothing, with zero-slope input edges. | `filters.smooth1d`, `smooth2d`, and `smooth3d` use SciPy Gaussian filters; rotate/shear scanner smoothing uses `scipy.ndimage.gaussian_filter1d`; `_gaussian_derivatives` uses SciPy Gaussian derivative filters for `scan_fast()`. | Recursive exponential response and edge behavior are not reproduced. | Python smoothing adapter tests exist; no JTK recursive-filter parity test. | Further parity testing can refine sigma mapping and edge behavior. |
| `getPhiSampling` / `getThetaSampling` and private sampling helpers | `strike_sampling` / `dip_sampling`; `reference_like_strike_sampling` / `reference_like_dip_sampling` | Public helpers use smoothing-dependent angle sampling; the inspected private scan path uses fixed strike sampling of 18 samples at 20 degrees and dip sampling near 5 degrees. | Default `scan()` uses `scan_reference_like()` sampling: the fixed 18-sample strike grid clipped to the requested range and approximately 5 degree dip spacing with requested endpoints preserved. The older smoothing-dependent `float32` NumPy linspace sampling is still exposed through `scan_fast()` and the public sampling helpers. | Java public and private scan sampling paths differ from each other; Python keeps fast and reference-like sampling separate and documented. | Python sampling regression tests cover both fast and reference-like sampling behavior; no Java sampling parity test. | No for the current approximation. |
| Normal vector conversion | `geometry.fault_normal_vector_from_strike_and_dip` | Java converts selected strike and dip to local fault-normal and related vectors for directional operations. | Python centralizes the same documented normal formula and uses it in scanning, thinning, cells, and voting. | Formula-level behavior is covered, but downstream use differs because scanner algorithms differ. | Geometry vector formula tests exist; no full Java scanner parity test. | No for current formula; verify again in a reference-like scanner audit. |
| Normalization / clipping | `_normalize_likelihood`; `_normalize_reference_like_likelihood` | Java scan clips interpolated likelihood to `[0, 1]` after unrotation and stores the best raw clipped value. | Reference-like mode clips the smoothed planarity response before applying `1 - smoothed**4`, clips unrotated likelihood candidates to `[0, 1]`, and optionally normalizes the final best score. `scan_fast()` clips nonnegative derivative-bank scores by the 99.5th percentile into `[0, 1]`. | Reference-like likelihood amplitude is affected by SciPy interpolation/smoothing and optional normalization, so it is still not Java-equivalent. | Python output range and deterministic behavior tests exist; no Java normalization parity test. | No for current reference-like semantics; revisit only with a fuller parity effort. |

## Java Methods Not Currently Represented

The current `pyosv.orient3d` scanner does not represent these Java
`FaultOrientScanner3` utilities as scanner features:

- `taper(...)`
- `getFrequencies(...)`
- `convertDips(...)`
- `convertStrikes(...)`
- 3D directional derivative helpers used by Java-side experiments
- null-slice rotated-array helpers used by `Rotator`

These are not needed by the current Python scanner. If a future issue
requires one of them, map and test that method independently before changing
scanner behavior.

## Reference-like scanner status

The current default scanner has the Java-like rotate/shear/smooth structure in
place, but the implementation remains a practical approximation. Follow-up work
should focus on scanner-only F3 reports, rotated-boundary behavior, sigma
mapping, and interpolation differences before interpreting integrated
scan-vote-thin changes as reference parity.
